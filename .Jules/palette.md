## 2024-06-21 - Accessible Responsive Navigation Links
**Learning:** Responsive utility classes (like Tailwind's `hidden sm:block`) hide text visually on smaller screens, but this also hides the content from screen readers. When an interactive parent (like `<Link>`) relies on this text for its accessible name, screen reader users on mobile devices are left with unlabelled, ambiguous links containing only an icon. Adding a visible focus state to navigation links is also essential for keyboard users to know which element is active.
**Action:** Always provide an explicit `aria-label` to interactive elements when their textual content might be hidden by CSS. When doing so, ensure child elements (like icons and the hidden text spans) have `aria-hidden="true"` to prevent screen readers from announcing redundant or confusing information. Also, use `aria-current="page"` to indicate active states, and define explicit focus ring styles (e.g. `focus-visible:ring-2 focus-visible:ring-[var(--accent)]`).
