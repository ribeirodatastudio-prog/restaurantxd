## 2025-10-24 - Missing Security Headers Mitigation
**Vulnerability:** The application was missing standard HTTP security headers globally (such as HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy).
**Learning:** Next.js uses an empty `next.config.js` by default without enforcing strict security headers out of the box. Leaving these headers absent exposes the application to common baseline web vulnerabilities like MIME sniffing, Clickjacking, non-HTTPS downgrades, and overly permissive referrer leaks.
**Prevention:** Always configure an `async headers()` method in `next.config.js` to define fundamental defense-in-depth security headers like `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, and `Referrer-Policy`.
## 2026-06-21 - Unhandled Database Errors and Missing Input Sanitization
**Vulnerability:** The application performed database operations (insert, update, delete) using Supabase without explicitly checking the returned `error` object and failed to validate user input lengths prior to insertions.
**Learning:** Supabase API interactions (`supabase.from(...).insert(...)`) do not automatically throw exceptions on database failures. If the `error` object isn't explicitly checked and thrown (`if (error) throw error`), failures are silently swallowed, allowing the UI to progress into invalid states. In addition, large or unbounded user inputs (like `name` or `notes`) without frontend length constraints represent a baseline Data Overload / DoS risk at the database level.
**Prevention:** Always wrap Supabase mutations in a `try...catch` block. Inside the `try`, apply length constraints (e.g., `substring(0, 100)`) to user strings and explicitly check for and throw the database `error` object. Display safe, generic feedback to the user via `alert()` and log the raw error object with `console.error` for debugging.
