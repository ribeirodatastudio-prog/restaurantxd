## 2025-10-24 - Missing Security Headers Mitigation
**Vulnerability:** The application was missing standard HTTP security headers globally (such as HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy).
**Learning:** Next.js uses an empty `next.config.js` by default without enforcing strict security headers out of the box. Leaving these headers absent exposes the application to common baseline web vulnerabilities like MIME sniffing, Clickjacking, non-HTTPS downgrades, and overly permissive referrer leaks.
**Prevention:** Always configure an `async headers()` method in `next.config.js` to define fundamental defense-in-depth security headers like `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, and `Referrer-Policy`.

## 2026-06-07 - Missing Input Validation and Unhandled DB Errors Mitigation
**Vulnerability:** User inputs were written directly to the database without length limits, risking Denial of Service (DoS) or unexpected database insertion failures. In addition, Supabase database calls (`.insert()`, `.update()`, `.delete()`) were not wrapped in `try...catch` blocks with explicit `throw` on `error`, meaning database failures would fail silently, breaking the application state without user feedback.
**Learning:** Next.js Server Actions and client-side database calls using Supabase require manual validation. Supabase methods do not throw JavaScript exceptions on failure; they return an `error` object. Ignoring this object masks critical database issues.
**Prevention:** Always enforce strict length and type limits on user inputs before database interaction (e.g., `substring(0, MAX)`, `isNaN()`). Always extract the `error` object from Supabase calls and explicitly `if (error) throw error` within a `try...catch` block. Provide generic user feedback via `alert()` and log the raw `error` object using `console.error()` for debugging.
